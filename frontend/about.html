Project Title: Decentralized Certificate Verification DApp Using Ethereum

Web3 & Solidity 0.8.x

Project Abstract

Academic certificate fraud and document counterfeiting pose serious challenges to educational institutions, recruiters, and credential verification agencies worldwide. Traditional verification requires manual correspondence, third-party clearinghouses, and days of processing time.

This mini project introduces a Decentralized Certificate Verification DApp built on the Ethereum blockchain using Solidity 0.8.x smart contracts, MetaMask wallet authentication, Ethers.js, and static Netlify deployment. Educational institutions digitally mint student certificate data directly onto the immutable Ethereum blockchain. Anyone can instantly verify the validity of a certificate by providing its unique Certificate ID or SHA-256 document hash without relying on central server infrastructure.

Technology Stack Breakdown

Solidity 0.8.x

Smart contract language defining state mappings, access control modifiers (`onlyAdmin`), duplicate checks, and event logging.

Ethers.js v5

Lightweight Web3 library connecting the HTML/JS frontend to Ethereum nodes and signed MetaMask transactions.

Netlify Hosting

Zero-backend static web hosting serving responsive HTML5, CSS3, and ES6 JavaScript directly to client browsers.

Quick Viva Voce Q&A Guide

Q1: How does blockchain ensure certificates cannot be forged?

Once a certificate is recorded inside the Ethereum smart contract mapping, its state is cryptographically signed and stored across thousands of decentralized nodes. Changing even a single character in a student's name would alter the cryptographic hash and fail validation on-chain.

Q2: Why does the frontend not require a traditional backend database server?

The Ethereum blockchain itself acts as a decentralized, globally distributed database. Ethers.js communicates directly with Ethereum JSON-RPC nodes via MetaMask, eliminating the need for Node.js, Express, or SQL servers on Netlify.

Q3: How is access control managed in the smart contract?

The contract maintains an `admin` state variable set to `msg.sender` upon deployment. The `issueCertificate` function uses the `onlyAdmin` modifier (`require(msg.sender == admin)`), preventing unauthorized users from issuing certificates.
